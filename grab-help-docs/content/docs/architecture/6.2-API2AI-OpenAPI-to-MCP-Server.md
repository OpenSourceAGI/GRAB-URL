The `api2ai` tool is a specialized generator within the GRAB-URL ecosystem designed to bridge the gap between structured API documentation and AI agent capabilities. It transforms any **OpenAPI specification** into a production-ready **Model Context Protocol (MCP)** server using the `mcp-use` framework [docs/content/docs/openapi-services/api2ai-mcp-server.mdx34-36](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L34-L36)

By leveraging OpenAPI metadata, `api2ai` automatically handles the heavy lifting of tool definition, Zod-based parameter validation, and secure HTTP transport, allowing LLMs to interact with complex backends with minimal manual glue code [docs/content/docs/openapi-services/api2ai-mcp-server.mdx40-49](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L40-L49)

## Implementation & Data Flow

The generation process involves parsing the OpenAPI spec, classifying the risk level of each endpoint, and emitting a Node.js project structure that implements the MCP protocol.

### Request Lifecycle

When an AI agent invokes a tool, the request flows through the following layers in the generated server:

1. **MCP Transport**: The request is received via HTTP, SSE, or Stdio [docs/content/docs/openapi-services/api2ai-mcp-server.mdx44](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L44-L44)
2. **Validation**: `mcp-use` validates the arguments against the generated **Zod schemas**[docs/content/docs/openapi-services/api2ai-mcp-server.mdx47](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L47-L47)
3. **Policy Gate**: `checkToolPolicy()` evaluates the risk level (`low`, `medium`, `high`) against environment variables like `ALLOW_RESTRICTED_TOOLS`[docs/content/docs/openapi-services/api2ai-mcp-server.mdx171-178](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L171-L178)
4. **HTTP Client**: The hardened client in `src/http-client.js` executes the actual API call with built-in timeouts and size caps [docs/content/docs/openapi-services/api2ai-mcp-server.mdx180-189](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L180-L189)

## Key Features

### Multi-Transport Support

Servers generated by `api2ai` support multiple communication methods required by different MCP hosts (like Claude Desktop or custom web interfaces):

- **HTTP/SSE**: For remote server deployments [docs/content/docs/openapi-services/api2ai-mcp-server.mdx44](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L44-L44)
- **Streamable HTTP**: Optimized for long-running tool executions [docs/content/docs/openapi-services/api2ai-mcp-server.mdx44](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L44-L44)
- **Stdio**: The default for local agent integrations like Claude Desktop [docs/content/docs/openapi-services/api2ai-mcp-server.mdx44](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L44-L44)

### Security Model

The generator enforces a three-layer security architecture [docs/content/docs/openapi-services/api2ai-mcp-server.mdx155-158](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L155-L158):

| Layer | Component | Role |
| --- | --- | --- |
| **Layer 1** | **Risk Classification** | Categorizes tools as `low` (GET), `medium` (Mutations), or `high` (Auth/Admin) at generation time [docs/content/docs/openapi-services/api2ai-mcp-server.mdx159-167](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L159-L167) |
| **Layer 2** | **Runtime Policy** | `checkToolPolicy()` gates execution based on `REQUIRE_APPROVALS` and `ALLOW_RESTRICTED_TOOLS` env vars [docs/content/docs/openapi-services/api2ai-mcp-server.mdx171-178](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L171-L178) |
| **Layer 3** | **HTTP Hardening** | Enforces `MAX_RESPONSE_BYTES`, `REQUEST_TIMEOUT_MS`, and prevents host-pivot attacks by disabling redirects [docs/content/docs/openapi-services/api2ai-mcp-server.mdx180-189](https://github.com/vtempest/GRAB-URL/blob/a61acaf0/docs/content/docs/openapi-services/api2ai-mcp-server.mdx?plain=1#L180-L189) |
